# Vietnam Career Agent Kit product goal

Bring your own AI agent and CV. Run an organized, evidence-based Vietnam job search with reusable tools and controlled application automation.

The product serves independent job seekers using their own private workspaces and agents, and maintainers developing the reusable toolkit. Maintainer tasks never initiate candidate intake, research or applications. Development uses fictional people and local portals only. No founder biography, contacts, preferences or applications belong in the product.

## Full product success criteria

1. Clone → diagnose → initialize an isolated private workspace → import CV evidence → confirm identity/preferences/facts → import or discover a JD → assess fit → prepare and review documents → approve an exact finite batch → receive permitted application outcomes or accurate manual handoffs → resume without duplicate final attempts.
2. One versioned portable core and canonical tracker, called by CLI and explicit runtime adapters. Existing agent reasoning is optional infrastructure, never a compulsory second paid model API.
3. Ten focused skills with shared factual/disclosure policy, synchronized host wrappers, honest runtime compatibility and bounded optional hooks.
4. English/Vietnamese user instructions and documents, preserved diacritics/official titles, explicit salary bases and unknown eligibility answers.
5. Separate discover/read/extract/fill/upload/submit/verify source permissions. Unknown writes require handoff. No universal coverage, employment, ATS or account-safety guarantees.
6. Exact, expiring candidate/employer/job/destination/artifact/answer/consent/action/limit authority, directly approved or derived from an explicitly approved bounded standing scope. Single-writer attempt recording before any possible final submission; unknown outcomes never retry automatically. Host confirmations remain separate.
7. Fictional multi-user tests for unsupported claims, conflicts, duplicates, localization, stale approvals, missing tools, rendering failures, browser interruptions and uncertain submissions. No paid model calls in deterministic CI and no fake employer applications.
8. Public-only source distribution: English/Vietnamese README, license/notices, contribution/security guides, dependency lock, compatibility/source registries, measured setup and safe upgrade/uninstall documentation.

The full product remains a multi-slice goal. A passing first slice does not prove browser support, rendered documents or approved-batch execution. See docs/roadmap.md for evidence and pending capabilities.

## Each user's setup and campaign goal

Default: **100 new best-fit confirmed applications**, counted from reviewed
Strong fit/Plausible fit and observed unique receipts in the user's own scope.
This is a total campaign target, not an hourly guarantee, job offer or grant of
disclosure authority. `start-campaign --cv FILE` creates a private intake/goal
packet; `--target N` overrides 100. See [CV-first setup](docs/COMMUNITY_START.md).
Only an explicit job-seeker request activates the campaign; cloning or maintaining
the product does not. Do not relax fit or import the public case-study rows to
inflate a new user's progress.

The [agent setup guide](docs/AGENT_SETUP.md) and [setup-and-goal prompt](prompts/SETUP_AND_GOAL.md)
let users supply their own runtime, private evidence, role scope, target and
limits. This product goal stays public; personal goals and receipts stay private.
Parallel applications depend on tested host isolation, not the number of agents
or browser tabs named in a prompt. Unidentified runtimes use a generic handoff.

## Current iteration acceptance — Slice 1

- Existing approval checks and legacy ledger behavior remain tested and usable.
- A new user can diagnose the selected runtime, initialize an external private workspace, import a fictional UTF-8 CV and versioned profile, inspect/confirm exact source-backed facts, import a structured JD, validate a complete evidence matrix, produce a truthful Markdown CV draft and resume/export its tracker record.
- A second fictional user in another workspace cannot read the first user's candidate or applications through these commands. Conflicting identities, unsupported fact links, unresolved conflicts, stale profile/JD content and out-of-root paths block affected operations.
- CLI results use versioned structured outcomes; missing tools/inputs never return empty success. Core tools have no third-party dependencies or external writes.
- Exact runnable commands, real test results and the next slice are documented. Later integrations are not labelled verified until tested in the named interface/version/OS.
