# Copy this: set up my agent and campaign goal

Fill the fields, then paste the whole block into your own tool-enabled AI agent.
Use `unknown` for missing facts. This works as portable instructions; it does
not install tools, certify a runtime or bypass its confirmations. Read
[agent setup](../docs/AGENT_SETUP.md) and [TinyFish setup](../docs/TINYFISH_SETUP.md).

```text
This is an explicit job-seeker setup request, not a toolkit-maintenance task.
Use Vietnam Career Agent Kit from my selected clone.

Clone path: [absolute local clone path]
Runtime/product/version: [actual Codex / Claude Code / Grokbot / Muse / other]
Private workspace: [one absolute directory outside the clone]
Authorized CV/evidence: [specific files or text I supply]
Existing checkpoint: [private reference or none]
Response/document language: [my choices]

My target roles, domain and seniority: [my choices]
Locations and remote-country eligibility: [explicit choices]
Employment types and exclusions: [my choices]
Prior applications: [tracker or supplied list]
Availability, work authorization and salary basis: [confirmed facts or unknown]

Campaign target: 100 new best-fit confirmed applications by default [explicit override if wanted]
Persistent host goal explicitly requested: [yes/no]
Research/preparation batch size and time limit: [finite limits]
Public providers: [none / TinyFish Fetch / other installed permitted reader]
Provider request/spending allowance: [finite reviewed limit or not authorized]
Parallel agent delegation permitted: [yes/no]
Requested browser lanes: [1-10, subject to tested host isolation]
Initial mode: PREPARE
Existing exact execution/standing authority: [private reference or none]
Close completed agent-owned tabs after saved confirmation: [yes/no]

1. Read docs/AGENT_SETUP.md, prompts/STARTUP.md and docs/job-seeker-policy.md.
   Diagnose the real runtime with the supported doctor choice and verify actual
   tools. For unidentified runtimes, use generic instructions without claiming
   native support. Do not install global settings, trust hooks or add a model API.
2. Reuse my selected workspace and canonical SQLite ledger. If new, initialize
   it only at my chosen external path. Back up existing state before an explicit
   schema upgrade. Never import fictional demo confirmations as my approval.
3. Use the ten shared skills by stage. Read only selected evidence. Confirm
   unresolved facts/conflicts once; reuse valid answers and authority. Unknown
   experience or screening answers stay unknown. Tailor wording, not my history.
4. If I explicitly requested a persistent goal and the host supports it, reuse
   the existing goal or create one if none exists. Otherwise save a private goal
   note without claiming scheduled/background work. Do not create a competing
   active goal. Preserve scope changes and previous confirmed history.
   For CV-first intake use start-campaign --cv FILE; target defaults to 100.
   Strong fit/Plausible fit qualify; do not lower fit to meet a quota. This local
   starter is not a running host goal, factual confirmation or disclosure approval.
5. Research a finite eligible batch. If TinyFish is selected, follow its setup
   guide: preview a public plan, use only privately configured credentials and
   dispatch once within its exact plan/budget. No candidate data goes to Fetch.
6. Screen full JDs, location, liveness and actual requirements. Skip duplicates
   and excluded roles; reconcile uncertain attempts read-only. Prepare grounded
   CVs and answers, perform a separate factual review, render and inspect pages.
7. Establish exact finite disclosure/execution scope before personal-data entry
   or upload. Reuse valid standing authority when it matches. Follow host/source
   requirements; changed recipients, files, answers or agreements need the
   applicable new review. Never auto-answer qualifications or consent yes.
8. If delegation is permitted, keep one coordinator/SQLite writer, compact public
   research tasks, grounded tailoring/review tasks and one owner per job. Browser
   workers return receipts only. Use available model IDs under my routing policy;
   deterministic checks use tools, and no more expensive fallback is automatic.
9. Use the request/receipt execution engine only with a permitted supported host
   bridge. Begin with one lane; expand to the tested isolated capacity, max ten.
   Multiple tabs sharing a login are one action stream. Do not invent browser
   sessions, native hooks or TinyFish Agent submission support. When no bridge
   exists, automate preparation and return an accurate manual handoff.
10. Persist an attempt before any possible final submission. Observe the actual
    matching outcome, save its immutable receipt, and close only that completed
    owned tab if requested. Never retry an uncertain send to increase the count.
11. Update my private tracker after every batch: employer/role, source, fit/gap,
    actual state, submitted time, receipt, blocker and next action. Report new
    confirmed, prior-reported, prepared, failed and uncertain counts separately.
12. Continue independent authorized work through finite batches. At expiry, cap,
    stop or a required user step, preserve a useful checkpoint. Mark the campaign
    complete only when the target and receipt reconciliation are satisfied. Do
    not promise a job, background execution or an unmeasured applications/hour.
```
