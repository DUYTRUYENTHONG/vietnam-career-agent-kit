# Refresh reviewed CV training data

Use this with a tool-enabled agent in your existing private workspace. Fill the
paths and job IDs below. This prompt does not install an unattended updater.

```text
Update my private, source-backed CV training dataset when new confirmed facts,
captured job requirements or reviewed wording are available.

Existing workspace: [absolute private workspace]
Selected new/corrected sources: [explicit files or source IDs]
Selected existing local job IDs: [IDs]
Previous dataset: datasets/reviewed-v1
New dataset: datasets/reviewed-v2
Training mode: prepare only unless a specific local/cloud run is already authorized

Read repository instructions and reuse the existing canonical tracker. Inspect
the current export and actual source changes first. Do not reset historical rows,
overwrite prior artifacts, initialize another tracker, or assume a model has been
trained because a directory exists.

Reconcile ownership, factual conflicts and obsolete CV versions. Use reference
resumes and role research only as references. Confirm new experience through the
normal evidence workflow. Keep private contacts, identity documents and unrelated
sensitive data out of model inputs. Professional facts and weights remain private.

Pair supported facts with exact captured employer clauses. Do not add technologies,
metrics, seniority or production experience to satisfy a requirement. Assess each
single-fact pair from that fact alone. Preserve AI assistance, prototype scope,
project tenure and numeric/time bases. Document partial or missing evidence.

Review actual wording independently, then use learning-export and learning-check
with the selected IDs and a new dataset directory. Keep the supported full-CV
output contract; do not silently substitute a bullet-only task. Review job/fact/
project/near-duplicate leakage and reserve untouched acceptance examples.

For an authorized experiment, validate token lengths and exact identities, train
into a new directory and record observed usage/time. Compare clean base and
matching adapter outputs, then compare separate prior/new experiment records only
when prompts and decoding are comparable. Do not promote on lower loss alone.
Do not restart an unknown live run merely because observation timed out.

Keep receipts and recruiter outcomes as separate, source-bound observations.
Do not infer CV-quality labels from sends, silence or unverified replies.

Report changed sources, accepted/excluded examples, split limitations, exact
artifact locations, actual training/evaluation status and the next unresolved
gate. Do not upload, publish, submit applications or install schedules merely
because this refresh prompt is present.
```
