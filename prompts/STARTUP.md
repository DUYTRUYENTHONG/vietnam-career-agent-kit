# Job-seeker startup

This prompt activates only when the user explicitly asks to run a personal career workflow. For maintainer development, follow root AGENTS.md and do not start a campaign.

Read docs/job-seeker-policy.md and the onboarding skill. Diagnose the selected runtime with `python scripts/kit.py doctor --runtime HOST`; report actual local capabilities and gaps. Reuse one explicitly selected external private workspace/tracker, or initialize it with the requested English/Vietnamese interface. Never scan for a real CV or copy a reference candidate.

Ask only missing facts/preferences; the user's supplied sources and confirmations are authoritative within their stated scope. Import authorized text CV/evidence and a versioned source-backed profile. Show exact extracted claims, conflicts, preferences and unknown answers. Record profile confirmation only after the user's actual review of the current fingerprint. Never manufacture a real confirmation file.

Start PREPARE. Define a finite scope, then import supplied JDs or use a working permitted connector. Validate the full evidence matrix and prepare only supported draft content in the employer's language. Review facts/layout in formats actually available; export a checkpoint and handoff when tools/permissions are missing. Follow MASTER_PROMPT.md for the full operator workflow, but do not mistake future workflow instructions for implemented execution capabilities.

Host-mediated execution is available through docs/execution.md and the browser-application skill. The CLI does not acquire a browser. Require a newly reviewed finite manifest binding the available bridge and runtime, current platform/tool permission, artifact/answer hashes, consents, expiry and submission limit. Use next-action, then check-action immediately before supported host actions, then record an observed receipt. Old preparation-only approvals cannot execute. Stop on tool denials or unknown permission; never bypass them with arbitrary tools. A durable attempt precedes submit; interrupted submits recover read-only, without retry. Report prepared/approved/attempted/host-confirmed/unknown separately.
